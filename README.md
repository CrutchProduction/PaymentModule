# PaymentModule

В этом проекте я реализовал учебный платёжный модуль на C# и WinUI 3. Приложение объединяет три лабораторные: банковские операции с контрактами, калькулятор слабейших предусловий и анализ будущих платежей с проверкой циклов.

## Использование

### Лабораторная №1 — Операции
Главное окно приложения разделено на две основные области: навигационный список доступных операций (слева) и панель выбранной операции (справа). Сверху отображается информация о текущем счёте пользователя, его балансе и валюте.

При выборе операции в списке отображается соответствующая панель с полями ввода, кнопкой выполнения и индикаторами валидации.

>#### **Перевод на другой счёт**
Позволяет перевести средства с текущего счёта на другой счёт.
- **Номер счёта** — отображается автоматически (только для чтения).
- **Номер счёта куда перевести** — поле ввода счёта получателя.
- **Сумма перевода** — поле ввода суммы перевода.

После заполнения полей необходимо нажать кнопку **«Перевести»**. Рядом с кнопкой отображается индикатор постусловия.

>#### **Перевод в другую валюту**
Позволяет конвертировать средства текущего счёта в выбранную валюту.
- **Номер счёта** — отображается автоматически (только для чтения).
- **Валюта** — выпадающий список с доступными валютами: Российский рубль ₽, Евро €, Доллар $, Юань ¥.

После выбора валюты необходимо нажать кнопку **«Конвертировать»**. Рядом с кнопкой отображается индикатор постусловия.

>#### **Пополнение**
Позволяет пополнить баланс текущего счёта.
- **Номер счёта** — отображается автоматически (только для чтения).
- **Сумма** — поле ввода суммы пополнения.

После ввода суммы необходимо нажать кнопку **«Пополнить счёт»**. Рядом с кнопкой отображается индикатор постусловия.

>#### **Снятие**
Позволяет снять средства с текущего счёта.
- **Номер счёта** — отображается автоматически (только для чтения).
- **Сумма** — поле ввода суммы снятия.

После ввода суммы необходимо нажать кнопку **«Снять»**. Рядом с кнопкой отображается индикатор постусловия.

>### **Контракты**
Для каждой операции доступна кнопка **«Показать контракт»**, при нажатии на которую открывается панель с описанием контракта операции, содержащая:
- **Предусловия** — условия, которые должны быть выполнены до операции.
- **Постусловия** — условия, которые должны быть выполнены после операции.
- **Эффекты** — изменения состояния системы.
- **Исключения** — возможные ошибочные ситуации.
- **Граничные примеры** — валидные и невалидные примеры выполнения операции.

>### **Индикаторы валидации**
Рядом с полями ввода и кнопками выполнения операций отображаются цветные прямоугольники, показывающие состояние валидации:
- **Зелёный** — условие выполнено (валидно).
- **Красный** — условие не выполнено (невалидно).

Цвет индикатора задаётся через конвертер `ConditionBrushConverter`, привязанный к соответствующим свойствам валидации ViewModel.

## Лабораторная №2 — Калькулятор предусловий

Во второй лабораторной я добавил калькулятор слабейшего предусловия wp. Он определяет, какое условие должно выполняться перед фрагментом программы, чтобы после его выполнения получить заданное постусловие.

В интерфейсе доступны три сценария:

- **Сколько нужно денег на несколько платежей** — необходимая начальная сумма для последовательности расходов с сохранением желаемого остатка.
- **Сколько нужно на перевод с комиссией** — перевод с комиссией, которая выбирается как максимум из процента от суммы и минимальной фиксированной комиссии.
- **Какая ставка нужна для накоплений за два года** — годовая ставка для достижения заданной суммы при ежегодном начислении процентов.

Пользователь выбирает сценарий, заполняет параметры, постусловие и код расчёта. Есть кнопка заполнения примером и подсказки у полей. Присваивания записываются через :=, например:

~~~text
balance := balance - 100;
balance := balance - 200;
~~~

Пример постусловия:

~~~text
balance >= reserve
~~~

Здесь reserve — желаемый остаток. Текущий баланс нужен для сравнения с необходимой суммой и определения недостающих средств.

Результат показывается справа. Для первых двух сценариев это необходимая сумма и недостающие средства, для третьего — годовая ставка. В блоке «Как получено условие» доступны преобразования wp, предусловие, условия определённости и триада Хоара. Ошибки ввода отображаются сообщением в интерфейсе.

## Лабораторная №3 — Анализ будущих платежей

В третьей лабораторной я связал обработку массивов с анализом будущих платежей. Пользователь вводит суммы в таблицу, выбирает расчёт и получает результат.

Доступные расчёты:

- Общая сумма платежей.
- Количество платежей больше указанной суммы. Для этого режима задаётся порог: например, среди платежей 100, 200 и 300 рублей больше 150 рублей — два платежа.
- Самый крупный платёж.

Количество строк можно менять. Для демонстрации есть заполнение случайными целыми суммами в заданном диапазоне. Текущая реализация работает с целыми рублями, без копеек. Кнопка «Как пользоваться» открывает инструкцию.

Например, для платежей 100, 200 и 300 рублей расчёт общей суммы выдаст **600 рублей**.

### Просмотр шагов и проверки цикла

После расчёта можно раскрыть «Проверка корректности расчёта». Слева находится история, справа — пошаговый просмотр. Кнопка «Шаг» переводит просмотр к следующему шагу, «Пуск/Пауза» управляет автоматическим просмотром, «Сброс» возвращает его в начало.

На каждом шаге отображаются текущий платёж, накопленный результат и проверки:

- **Инвариант до и после шага.** В режиме суммы правило означает, что накопленный результат равен сумме уже обработанных платежей.
- **Вариант-функция.** По умолчанию это n - j, где n — количество платежей, j — количество обработанных. Проверяется, что значение строго уменьшается и остаётся неотрицательным. Изменение видно в истории и рядом с прогресс-баром.
- **Постусловие.** После завершения проверяется соответствие результата выбранному расчёту.

Инвариант задаётся словами и формулой, вариант — формулой. Для каждого режима они заполнены заранее. Изменённые формулы участвуют в проверках; после изменения данных или формул нужно выполнить расчёт заново.

Пример инварианта для суммы:

~~~text
res == sum(a, 0, j) && 0 <= j && j <= n
~~~

Для остальных режимов используются функции count_gt(a, 0, j, T) и max_prefix(a, 0, j).

Ниже показаны четыре условия корректности: инициализация, сохранение инварианта, выход и завершение. Движок из второй лабораторной вычисляет wp для инициализации и тела цикла, включая условие убывания варианта. old_t обозначает значение варианта перед шагом. В бэке также предусмотрены Debug.Assert для встроенного инварианта алгоритма и журнал выполнения.

**Границы проверки:** программа вычисляет формулы wp и проверяет условия на введённых данных. Это не автоматическое доказательство корректности для всех возможных массивов. Неверный инвариант, неубывающий вариант или ошибка формулы отображаются как нарушение либо сообщение об ошибке.

## Устройство проекта и проверки

- PaymentModule — интерфейс WinUI 3, представления и ViewModel.
- PaymentClassLibrary — логика платёжного модуля и движок wp. В PaymentLoop.cs находятся расчёты третьей лабораторной, история и проверки формул.
- PaymentClassLibTest — автоматические тесты проекта на MSTest.

Для сборки в Visual Studio нужны .NET 8, средства разработки WinUI и Windows SDK. Основное приложение собирается в конфигурации **Release x64**.

Запуск тестов:

~~~powershell
dotnet test PaymentClassLibTest/PaymentClassLibTest.csproj -p:Platform=x64
~~~

Отдельная проверка циклов и движка wp:

~~~powershell
dotnet test PaymentClassLibTest/PaymentClassLibTest.csproj -p:Platform=x64 --filter "FullyQualifiedName~PaymentLoopTests|FullyQualifiedName~WpEngineTests"
~~~

В тестах циклов проверяются три режима на 120 небольших массивах, итоговые результаты, убывание варианта, ошибочные формулы и подстановка в выражениях с массивами. Добавлены отдельные проверки суммы по шагам, строгого порога, максимума в начале списка, нулевых платежей, одного платежа и пустого списка. Два неработающих теста конвертации валют удалены. При последней проверке прошли все 18 тестов проекта, из них 10 тестов циклов и один тест движка wp.
